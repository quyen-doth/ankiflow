## 1. はじめに

### 1.1 本書の目的

本書は、AnkiFlow が満たすべき要件を定義する。何を、誰のために、なぜ実現するのかを示し、実現方式は各設計書に委ねる。

### 1.2 適用範囲

本書が対象とするのは、AnkiFlow のアプリケーション本体、および外部サービスとの連携要件である。Anki Desktop 本体、AnkiWeb、および利用者の学習方法そのものは対象外とする。

### 1.3 用語

本書で用いる用語は用語集 (AF-GLS-001) に従う。

### 1.4 本書の位置づけに関する注記

初版は開発着手時点 (2026-04-15) の要件として作成した。その後、単一利用者・ローカル実行の構成から、Firebase 認証によるマルチユーザー構成へ発展している。第 2.0 版では、実装済みの機能を正として全面的に改訂した。

## 2. 背景と課題

### 2.1 現状 (As-Is)

Anki で語彙カードを手作業で作成する場合、1 枚あたり次の作業が発生する。

1. 意味、例文、発音、品詞、レベルをそれぞれ調べる
2. 画像と音声を個別に用意する
3. 出題方向の異なるカード (単語から意味、意味から単語、音声から単語など) を 1 枚ずつ作る
4. 過去に作成済みかどうかを記憶に頼って判断する

### 2.2 課題

| 課題 | 影響 |
| --- | --- |
| 1 枚あたりの作成時間が長い | 学習そのものより準備に時間を取られ、継続が途切れる |
| 作成手順が定まっていない | カードごとに情報量と品質がばらつく |
| 作成履歴が残らない | 同じ語を重複して登録する |
| Anki Desktop を開かないと復習しない | 学習機会が机に向かう時間に限定される |

## 3. システム化の方針

### 3.1 方針

カードを作る手間をなくすことに集中する。間隔反復 (SRS) の中核である出題スケジューリングと復習体験は、実績のある Anki に委ねる。

### 3.2 主要目標

| 目標 | 測定指標 |
| --- | --- |
| カード 1 枚あたりの作成時間を短縮する | 入力開始から Anki への登録完了までの所要時間 |
| 1 回の入力から複数の出題方向のカードを生成する | 1 語あたりに生成されるカード種類数 |
| 複数の学習言語と分野に対応する | 対応するコンテンツタイプ数 |
| 運用コストを抑える | 月あたりの外部 API 費用 |
| 机に向かわない時間にも復習機会を作る | 通知経由の復習回数 |

目標値および測定方法は効果測定計画書 (AF-EVL-001) に定める。

## 4. 利用者と利用シーン

### 4.1 利用者区分

| 区分 | 説明 | 権限 |
| --- | --- | --- |
| 管理者 | アプリケーションの所有者。外部 API の費用を負担する | 全機能に加え、全体設定と新規利用者向け既定データの編集 |
| 利用者 | 招待を受けて利用する学習者 | 自身のワークスペース内の全機能 |

利用者間のデータは完全に分離する。他者のデータを参照する機能は提供しない。

現時点で公開サインアップは無効であり、利用者は管理者の招待によってのみ追加される。

### 4.2 利用シーン

| シーン | 端末 | 内容 |
| --- | --- | --- |
| カード作成 | PC (ブラウザ) | 語彙を入力し、内容を確認して Anki へ登録する |
| 復習 | PC、タブレット、スマートフォン | Anki および AnkiWeb 同期経由で学習する |
| 受動的復習 | スマートフォン | 通知に届いた内容をその場で確認する |

## 5. 業務フロー

### 5.1 To-Be フロー — カード作成

```
[1]  ログインする
[2]  コンテンツタイプ・デッキ・カテゴリなどを選択する
       └─ 前回の選択内容はセッションに保持されるため、通常は再選択不要
[3]  語彙または用語を入力する
[4]  生成を実行する
       ├─ AI がカード内容を生成する
       ├─ 画像を取得する
       └─ 音声を生成する
[5]  プレビューで内容を確認し、必要に応じて編集する
[6]  登録方法を選ぶ
       ├─ Anki 起動中   → AnkiConnect でノートを作成し、状態を synced として保存
       └─ Anki 未起動   → 状態を reviewed として保存し、後からまとめて同期
[7]  入力欄が初期化され、選択条件は保持されたまま次の語へ進む
[8]  Anki Desktop を AnkiWeb と同期し、任意の端末で学習する
```

### 5.2 To-Be フロー — 受動的復習

```
[1]  利用者が LINE アカウントを連携する
[2]  システムが FSRS に基づき復習期日を算出する
[3]  管理者が設定した配信時刻に、利用者のタイムゾーンで判定する
[4]  対象がある利用者へ復習内容を通知する
[5]  利用者は通知上で内容を確認する
```

## 7. 機能要件詳細

本章では、他の設計書で扱わない要件のみを詳述する。

### 7.1 FR-020 入力条件のセッション保持

連続して複数のカードを作成する場合、利用者が入力するのは新しい語彙だけでよく、それ以外の選択は前回の状態を保持する。

| コンテンツタイプ | 保持する項目 | 毎回初期化する項目 |
| --- | --- | --- |
| 語学 | 学習言語、デッキ、カテゴリ、タグ、カードタイプ | 語彙、メモ |
| IT 用語 | デッキ、トピック、難易度 | 用語、定義、キーワード |
| 一般知識 | デッキ | タイトル、内容 |

保持状態はコンテンツタイプごとに独立して保存する。コンテンツタイプを切り替えた場合は、切り替え先の保持状態を読み込む。

デッキに既定のカテゴリまたは既定のカードタイプが設定されている場合、デッキの選択時にそれらを自動的に反映する。

### 7.2 FR-017 重複検出

生成を実行する前に、同一利用者の登録済みカードから同じ語を検索し、存在する場合は警告する。警告後も、利用者の判断で作成を続行できる。

### 7.3 FR-042 遅延同期

Anki が起動していない場合でも、生成した内容を失わずに保存できる。保存された内容は状態 `reviewed` として扱い、Anki の起動後にまとめて同期できる。同期が完了した内容は状態 `synced` へ遷移する。

## 9. データ要件

保持するデータの構造、コレクション間の関係、および利用者間のアクセス制御はデータベース設計書 (AF-DB-001) に定める。

Anki へ書き出すカードの構成はカードテンプレート仕様書 (AF-CRD-001) に定める。

## 10. 外部インターフェース要件

| 連携先 | 用途 | 要件 |
| --- | --- | --- |
| Claude API | カード内容の生成 | 構造化された出力を得ること。自由文での応答を許容しない |
| Google Cloud TTS | 音声の生成 | 学習言語に対応した音声を選択できること |
| Unsplash API | 画像の取得 | 生成された検索語で画像を取得できること |
| AnkiConnect | Anki への登録 | 利用者自身の端末上の Anki に対して動作すること |
| LINE Messaging API | 復習通知 | 利用者ごとに宛先を解決して配信できること |

各連携の詳細な仕様は API 設計書 (AF-API-001)、通信経路と実行主体はアーキテクチャ設計書 (AF-ARC-001) に定める。

## 11. 非機能要件

性能、可用性、セキュリティ、および運用コストに関する要件は非機能要件書 (AF-NFR-001) に定める。

現時点で把握している運用コストの前提は次のとおりである。Firestore、Google Cloud TTS、Unsplash はいずれも無料枠の範囲内で運用することを前提とし、実費が発生するのは Claude API のトークン課金のみである。実績値の測定は効果測定計画書 (AF-EVL-001) に従う。

## 12. 前提条件・制約条件

### 12.1 前提条件

| 項目 | 内容 |
| --- | --- |
| Anki Desktop | 利用者の端末に導入され、AnkiConnect アドオンが設定済みであること |
| AnkiConnect の CORS 設定 | アプリケーションのオリジンが `webCorsOriginList` に登録されていること |
| ブラウザ | Chrome、Edge、または Firefox を用いること |
| 端末間の同期 | Anki Desktop と AnkiWeb の同期は利用者が実施すること |

### 12.2 制約条件

| 項目 | 内容 |
| --- | --- |
| AnkiConnect の呼び出し | サーバーからは実行できない。ブラウザが利用者自身の端末に対して直接実行する |
| ブラウザのローカルネットワークアクセス制限 | 公開オリジンから `localhost` への通信はブラウザ側の方針で遮断される場合がある。アプリケーション側では回避できない |
| Safari | HTTPS ページから `localhost` への接続を許可しないため、Anki 連携には使用できない |
| 認証方式 | メールアドレスとパスワードのみ。外部 ID プロバイダには対応しない |
| 外部 API の費用 | 管理者が負担するため、費用の発生する機能は管理者が全体で制御できること |

## 13. スコープ外

以下は本システムの対象外とする。

| 項目 | 理由 |
| --- | --- |
| 独自の SRS エンジン | 出題スケジューリングは Anki に委ねる方針であるため |
| Anki を介さない直接の端末同期 | Anki および AnkiWeb の同期機構を利用する前提であるため |
| 利用者間でのデータ共有・公開 | 個人の学習記録を扱うため、共有機能は設けない |
| 学習そのものの実施 | 復習は Anki 上で行う。本システムは通知による導線までを担う |
| 外部 ID プロバイダによる認証 | 招待制の運用であり、必要性がないため |
