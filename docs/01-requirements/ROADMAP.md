## 1. 本書の位置づけ

本書は、AnkiFlow の開発段階と今後の計画を定義する。各段階の完了判定基準、および `1.0.0` へ移行する条件を示す。

本書は前身である `docs/PRD.md` の第 16 章「ロードマップ」および第 17 章「MVP 完了基準」を引き継いだものである。旧文書では Phase 1 の全項目が未完了として記載されていたが、実際には実装が完了していたため、本書では実装状況を正として記載を改めた。

実装状況の判定は 2026-08-01 時点 (v0.13.1) のものであり、根拠は要件定義書 (AF-REQ-001) 第 6 章の機能要件一覧である。

| --- | --- | --- |
| 1 | 中国語カードを作成できる (漢字、ピンイン、漢越音、意味、例文、コロケーション、音声、画像) | 達成 |
| 2 | 日本語カードを作成できる (漢字、ひらがな、意味、例文、コロケーション、音声、画像) | 達成 |
| 3 | 英語カードを作成できる (単語、IPA、意味、例文、コロケーション、音声、画像) | 達成 |
| 4 | IT 用語カードを作成できる (用語、定義、例え、キーワード、画像) | 達成 |
| 5 | 作成前にプレビューで確認し、各項目を編集できる | 達成 |
| 6 | カードの表示が崩れず、端末を問わずフォントが破綻しない | 達成 |
| 7 | セッション永続化により、次の語は入力欄だけで作成できる | 達成 |

基準 12 について、Claude API のみ従量課金であり、無料枠が存在しない。実費の実測は効果測定計画書 (AF-EVL-001) に従う。前提と内訳は非機能要件書 (AF-NFR-001) 第 5 章に定める。

基準 6 のうち、旧文書が挙げていた「Anki mobile における CJK フォントの表示不良」については、カードテンプレート仕様書 (AF-CRD-001) 第 6 章のとおり、フォントのフォールバック指定によって対処している。外部フォントの読み込みは行わないため、利用者の端末に該当フォントが存在しない場合は指定順のフォールバックが適用される。

## 4. `1.0.0` への移行条件

バージョン `1.0.0` は、データモデル (コンテンツタイプ、カードタイプ、AI 出力プロファイル、および Anki ノートタイプのフィールド構成) が実利用を通じて安定し、移行スクリプトを要する変更が発生しなくなったと判断した時点で付与する。利用者数や公開サインアップの有無は判断材料としない。

判定の詳細と、移行時に「公開 API の定義」を追記する義務については、開発規約 (AF-DEV-001) の「バージョニング規則」に定める。

## 5. 優先順位の考え方

未着手項目に着手する順序は、次の基準で判断する。

1. 現に運用を妨げている問題の解消を最優先とする
2. 次に、文書体系の未作成分 (AF-NFR-001 以降の各文書) を埋める
3. 機能追加は、カード作成の所要時間を短縮するものを優先する。学習体験そのものに関わる機能は Anki に委ねる方針であるため、優先度を下げる
