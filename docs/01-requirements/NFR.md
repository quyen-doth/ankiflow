## 1. 本書の位置づけ

本書は、要件定義書 (AF-REQ-001) 第 11 章から委譲された非機能要件を定義する。対象は、性能、可用性、セキュリティ、運用コスト、および保守性である。

本書は前身である `docs/PRD.md` 第 14 章「コスト分析」および第 15 章「制限とリスク」を引き継ぎ、現行の構成に合わせて記述を改めたものである。

本書における数値は、明示のない限り**目標値ではなく前提値**である。個人開発かつ利用者数が限られる段階にあり、実測に基づく目標設定は効果測定計画書 (AF-EVL-001) の策定後に行う。根拠のない目標値を掲げないという方針による。

## 2. 性能

### 2.1 応答時間

| 処理 | 支配的な要因 | 現状の位置づけ |
| --- | --- | --- |
| 画面遷移、一覧表示 | Firestore の読み取り | 利用者が待たされない範囲に収まっている |
| AI によるカード内容の生成 | Claude API の応答 | 数秒を要する。ローディング表示で状態を伝える |
| 音声生成 | Google Cloud TTS の応答 | 生成と保存を分離し、保存のみの再試行を可能にしている |
| 画像取得 | Unsplash API の応答 | 取得できない場合は画像なしで続行できる |
| Anki への登録 | 利用者端末の AnkiConnect | ネットワークを経由しないため高速である |

外部 API に依存する処理は、いずれも所要時間をアプリケーション側で制御できない。したがって、応答時間そのものを要件とはせず、**待ち状態を利用者に明示すること**、および**失敗しても入力内容を失わないこと**を要件とする。

実測の手順は効果測定計画書 (AF-EVL-001) 第 4 章に定める。結果は効果測定報告書 (AF-EVL-002) 第 3 章に記録し、確定後に本節へ実測値を反映する。

### 2.2 データ量の前提

| 対象 | 前提 |
| --- | --- |
| 利用者数 | 招待制であり、当面は 10 名未満を想定する |
| 1 利用者あたりのエントリ数 | 数千件の規模を想定する |
| Firestore の総容量 | 無料枠 1 GB の範囲に収まることを前提とする |

### 2.3 クエリ設計上の制約

- Firestore には JOIN が存在しない。関連ドキュメントは `Promise.all()` による一括取得で解決し、ループ内で逐次取得してはならない。
- 一覧画面で用いる複合条件は、あらかじめ複合インデックスを `firestore.indexes.json` に宣言する。
- 容量の大きいメディア用フィールド (`audio_url`、`audio_example_url`、`image_url`) は検索および並べ替えに用いないため、単一フィールドインデックスを無効化する。

詳細はデータベース設計書 (AF-DB-001) に定める。

## 3. 可用性

### 3.1 前提

本システムは、業務システムとしての可用性保証を持たない。個人の学習用途であり、停止によって直ちに損害が生じる性質のものではないためである。稼働率の目標値は定めない。

### 3.2 外部依存と縮退動作

各外部サービスが利用できない場合の挙動を次に定める。いずれの場合も、**利用者の入力内容を失わないこと**を必須とする。

| 依存先 | 停止時の挙動 | 縮退の可否 |
| --- | --- | --- |
| Firestore | 読み書きが失敗する | 不可。中核機能が停止する |
| Claude API | カード内容を生成できない | 不可。ただし一般知識タイプは AI を用いないため利用できる |
| Google Cloud TTS | 音声を生成できない | 可。音声なしでカードを作成できる |
| Unsplash API | 画像を取得できない | 可。画像なしでカードを作成できる |
| AnkiConnect | Anki へ登録できない | 可。状態 `reviewed` として保存し、後から一括同期する (FR-042) |
| LINE Messaging API | 通知を配信できない | 可。通知は補助機能である |

### 3.3 費用の発生する機能の停止手段

Claude API、Google Cloud TTS、Unsplash は管理者が費用を負担する。管理者は `settings/global` のフィーチャーフラグにより、これらの機能を全体で無効化できる (FR-070)。想定を超える利用や費用が発生した場合の停止手段として位置づける。

## 4. セキュリティ

セキュリティ設計の詳細はセキュリティ設計書 (AF-SEC-001) に定める。本節では要件のみを示す。

| # | 要件 |
| --- | --- |
| 1 | 認証されていない利用者は、いかなる業務データにも到達できないこと |
| 2 | 利用者は自身のワークスペース以外のデータを参照・変更できないこと。この制約はアプリケーション層だけでなく、データベース層 (Firestore Security Rules) でも強制すること |
| 3 | 認証情報をブラウザの JavaScript から読み取れないこと (httpOnly セッションクッキーを用いる) |
| 4 | 管理者判定は、サーバー側と Firestore Security Rules の双方で独立に成立すること |
| 5 | 外部システム向けおよび定期実行向けのエンドポイントは、セッションとは独立した共有シークレットで保護し、比較は時間一定で行うこと |
| 6 | 外部サービスの資格情報をクライアントへ配布しないこと |
| 7 | 公開サインアップは既定で無効とし、明示的に有効化した場合にのみ動作すること (fail-closed) |

脆弱性の報告窓口は `SECURITY.md` に定める。

## 5. 運用コスト

### 5.1 内訳

| サービス | 無料枠 | 想定使用量 | 費用 |
| --- | --- | --- | --- |
| Firebase Firestore | 1 GB、読み取り 5 万件/日、書き込み 2 万件/日 | 前提のデータ量の範囲内 | 無料 |
| Firebase Authentication | メール/パスワード認証は無制限 | 招待制、10 名未満 | 無料 |
| Claude API (`claude-haiku-4-5`) | なし (従量課金) | カード 1 枚あたり 1 リクエスト | **従量課金** |
| Google Cloud TTS | 100 万文字/月 (WaveNet) | カード 1 枚あたり数百文字 | 無料 |
| Unsplash API | 50 リクエスト/時 (Demo 区分) | カード 1 枚あたり 1 リクエスト | 無料 |
| AnkiConnect | — | 利用者端末で動作する | 無料 |
| AnkiWeb 同期 | — | — | 無料 |
| ホスティング (Vercel) | Hobby 区分 | 個人利用 | 無料 |

実費が発生するのは Claude API のトークン課金のみである。

### 5.2 費用に関する要件

| # | 要件 |
| --- | --- |
| 1 | 通常の利用において、Claude API 以外は無料枠の範囲に収まること |
| 2 | 費用の発生する機能を管理者が全体で停止できること |
| 3 | 不要なリクエストを発生させないこと。例として、例文音声の生成は、当該ブロックを用いるカードタイプを選択している場合にのみ実行する |

### 5.3 実測

トークン単価および実際の請求額は変動する。本書には単価を記載しない。実測値と単位あたりの費用は効果測定計画書 (AF-EVL-001) および効果測定報告書 (AF-EVL-002) に記録する。

測定の手順は効果測定計画書 (AF-EVL-001) 第 5.3 節に、結果は効果測定報告書 (AF-EVL-002) 第 7 章に定める。

## 6. 保守性

| # | 要件 |
| --- | --- |
| 1 | TypeScript の strict モードを維持し、`any` を用いないこと |
| 2 | ルーティングおよび状態を表す値は列挙型で定義し、文字列を直接記述しないこと |
| 3 | 実装を変更した場合、対応する設計書を同一の Pull Request で更新すること (対応関係は AF-DEV-001 に定める) |
| 4 | Firestore のスキーマを変更する場合、既存データに対する移行手段を用意し、既定を dry-run とすること |
| 5 | 利用者向けの表示文字列はすべて英語で統一すること |

## 7. 残存リスク

前身文書の第 15 章を引き継ぎ、現行構成における状況を示す。

| リスク | 影響度 | 対策 | 状況 |
| --- | --- | --- | --- |
| ブラウザのローカルネットワークアクセス制限により、公開オリジンから `localhost` へ到達できない | 高 | 回避不能。状況を判定して案内文を出し分ける | **未解消** |
| AnkiConnect が応答しない | 高 | 起動手順と CORS 設定の案内を表示する | 対処済み |
| AnkiConnect の CORS 設定漏れと Anki 未起動を区別できない | 中 | ブラウザが詳細を秘匿するため区別不能。両方の可能性を案内する | **未解消** |
| Safari から Anki 連携を利用できない | 中 | 回避不能。他ブラウザの利用を案内する | **未解消** |
| AI が想定外の構造で応答する | 低 | tool 呼び出しの強制と Zod による検証 | 対処済み |
| 適切な画像が見つからない | 中 | 検索語の再指定、または画像なしでの続行を許容する | 対処済み |
| 同じ語を重複して登録する | 中 | 生成前に登録済みの語を検索して警告する (FR-017) | 対処済み |
| TTS の割り当てを無駄に消費する | 中 | 生成と保存のルートを分離し、保存のみ再試行できるようにする | 対処済み |
| Firestore が一時的に利用できない | 低 | 縮退不可。エラーとして扱う | 受容 |

「未解消」の 3 件はいずれもブラウザの仕様に起因し、アプリケーション側では回避できない。利用者への案内をもって対応とする。詳細はアーキテクチャ設計書 (AF-ARC-001) に記載する。
