## 3. 読む順序

読み手の目的によって、読むべき文書と順序は異なる。

### 3.1 プロジェクトに新しく参加する場合

1. 本書（AF-IDX-001）で文書全体の構成を把握する
2. 要件定義書（AF-REQ-001）で、何を、なぜ作っているのかを理解する
3. アーキテクチャ設計書（AF-ARC-001）で、システム全体の構成とデータの流れを把握する
4. 環境構築手順書（AF-SET-001）に従って、ローカル環境を構築する
5. 開発規約（AF-DEV-001）で、ブランチ運用とコミット規約を確認する

### 3.2 日常の開発を行う場合

用語に迷った場合は用語集（AF-GLS-001）を参照する。そのうえで、変更対象に応じて以下の文書を読む。

| 変更対象 | 参照する文書 |
| --- | --- |
| API ルートの追加・変更 | AF-API-001 |
| Firestore のクエリ・スキーマ | AF-DB-001 |
| 画面・UI コンポーネント | AF-UI-001、AF-SCR-001 |
| AI 生成の挙動 | AF-PRM-001 |
| Anki カードの構成 | AF-CRD-001 |
| 検証仕様（`verify/`） | AF-VER-001 |
| テストの追加・変更 | AF-TST-001 |

### 3.3 設計判断の背景を確認する場合

アーキテクチャ決定記録（AF-ADR-nnnn）を参照する。技術選定の理由、検討した代替案、および採用によって生じた影響が記録されている。

### 3.4 プロダクトの成果を確認する場合

1. 要件定義書（AF-REQ-001）で、当初の目的と課題を確認する
2. 効果測定計画書（AF-EVL-001）で、測定の設計と指標の定義を確認する
3. 効果測定報告書（AF-EVL-002）で、測定結果と考察を確認する

### 3.5 アプリケーションを利用する場合

利用ガイド（AF-USR-001）を読み、問題が生じた場合は FAQ（AF-USR-002）を参照する。

## 4. 識別子の読み方

各文書には、以下の識別子が用いられている。文書中でこれらの記号に出会った場合は、本節を参照すること。

| 種別 | 形式 | 例 | 意味 |
| --- | --- | --- | --- |
| 文書ID | `AF-{区分}-{連番}` | `AF-REQ-001` | 文書そのものを一意に指す。ファイル名や配置が変わっても不変である |
| 機能要件 | `FR-{連番}` | `FR-012` | 要件定義書に定義された個々の機能要件 |
| 画面 | `SC-{連番}` | `SC-003` | 画面設計書に定義された個々の画面 |
| テストケース | `TC-{連番}` | `TC-045` | テスト計画書に定義された個々のテストケース |
| アーキテクチャ決定記録 | `ADR-{4桁連番}` | `ADR-0001` | 個々の設計判断の記録 |

機能要件（`FR-`）とテストケース（`TC-`）は、テスト計画書のトレーサビリティマトリクスで相互に対応付けている。ある要件がどのテストで担保されているかを確認する場合は、当該マトリクスを参照すること。
