## 1. 本書の位置づけ

本書は、AnkiFlow が当初の目的をどの程度果たしたかを測るための、測定の設計を定義する。何を、どのように測り、その結果をどこまで主張してよいかを事前に定めることを目的とする。

測定の結果は効果測定報告書 (AF-EVL-002) に記録する。**本書は測定を実施する前に確定させる。** 結果を見てから指標や判定基準を決めることは、都合のよい数値を選ぶ余地を生むためである。

要件定義書 (AF-REQ-001) 第 3.2 節に定めた 5 つの主要目標が測定の対象である。

## 2. 測定の基本方針

### 2.1 二層に分けて扱う

本システムが与える影響は、性質の異なる二層からなる。両者を混ぜて論じてはならない。

| 層 | 内容 | 本書での扱い |
| --- | --- | --- |
| **業務効率** | カードを作る作業そのものの負担 | **測定の中心とする。** 実測し、数値で示す |
| **学習効果** | 語彙の定着や学習の成果 | **測定しない。** 仮説として提示し、代替指標を参考値として添えるにとどめる |

学習効果を測定対象から外す理由は第 6 章に述べる。要約すれば、本測定の設計では因果を主張できないためである。

### 2.2 誠実さを設計に組み込む

本測定は、**開発者本人が、自分の作ったツールを、自分で測る**という構造を持つ。この構造には期待バイアスが内在する。

したがって次を方針とする。

| # | 方針 |
| --- | --- |
| 1 | 測定手順と判定基準を実施前に確定し、本書に固定する |
| 2 | 都合の悪い結果も記録する。外れ値を無断で除外しない |
| 3 | 主張できる範囲を第 6 章で明示し、それを超える結論を書かない |
| 4 | 生データを報告書に残し、集計値だけを示さない |

方針 4 は重要である。集計値のみを示す報告は検証できない。個々の測定値を残せば、読み手が自分で判断できる。

## 3. 測定指標

要件定義書の主要目標に対応させ、`M-nn` の識別子を与える。

| 指標ID | 対応する目標 | 測定内容 | 種別 |
| --- | --- | --- | --- |
| M-01 | カード 1 枚あたりの作成時間を短縮する | 入力開始から Anki への登録完了までの所要時間 | 実測 (実験) |
| M-02 | 1 回の入力から複数の出題方向のカードを生成する | 1 語あたりに生成されるカード種類数 | 実測 (計数) |
| M-03 | 複数の学習言語と分野に対応する | 対応するコンテンツタイプ数 | 計数 |
| M-04 | 運用コストを抑える | カード 1 枚あたりの外部 API 費用 | 実測 (請求額) |
| M-05 | 机に向かわない時間にも復習機会を作る | 通知経由で復習した回数 | 実測 (ログ) |

M-01 が中心である。第 4 章でその手順を詳述する。M-02 から M-05 は第 5 章にまとめる。

## 4. M-01 — 作成時間の測定

### 4.1 設計

**被験者内比較 (within-subject) による A/B 実験**とする。同一人物が、同じ条件下で、手作業と AnkiFlow の両方によりカードを作成し、所要時間を比較する。

対照群を置く余地がないため、被験者自身が対照を兼ねる。この設計上の限界は第 6 章に記す。

### 4.2 等価性の定義

**これが本測定において最も重要な取り決めである。**

作成時間を比較するには、両方式が**同じ完成度のカードを作っていること**が前提となる。手作業で意味だけを書いたカードと、AnkiFlow が意味・例文・発音・画像・音声まで揃えたカードを比べれば、時間差は当然生じる。それは効率の差ではなく、成果物の差である。

したがって、**完成の条件**を次のとおり定める。両方式ともこの条件を満たして初めて「1 枚完成」とする。

| # | 必須項目 | 備考 |
| --- | --- | --- |
| 1 | 見出し語 | — |
| 2 | 意味 | — |
| 3 | 品詞 | 語学系のみ |
| 4 | 読み (ひらがな・ピンイン・IPA のいずれか) | 学習言語に応じる |
| 5 | 例文 | 1 文以上 |
| 6 | 例文の訳 | — |
| 7 | 単語音声 | — |
| 8 | 画像 | — |
| 9 | Anki への登録完了 | 指定デッキに入り、Anki 上で表示できる状態 |

手作業側でいずれかを省略した場合、その回は**「条件未達」として記録し、集計から除外せず、未達である旨を明記する**。除外すると手作業側が不当に速く見えるためである。

### 4.3 語彙の準備

| # | 手順 |
| --- | --- |
| 1 | 未登録の語を 20 語選ぶ。既に作成済みの語は使わない (調べる手間が変わるため) |
| 2 | 同一の学習言語、同程度の難易度でそろえる |
| 3 | 10 語ずつ 2 群に分け、語群 A・語群 B とする |
| 4 | 群への割り当ては恣意的に行わない。並べた順に交互へ振るなど、機械的な規則による |

手順 4 は、無意識に「簡単な語を AnkiFlow 側へ寄せる」ことを防ぐための措置である。

### 4.4 実施順序

順序効果への対策を要する。先に実施した側で語彙領域に慣れるため、後に実施した側が有利になるためである。

対策の強さが異なる 3 案を示す。**上ほど望ましいが、下でも測定は成立する。** 実施可能なものを選び、選んだ案を報告書に明記する。

| 案 | 手順 | 順序効果 |
| --- | --- | --- |
| **推奨** | 語を 2 語ずつ交互に、方式を切り替えながら作成する | ほぼ相殺される |
| 次善 | 日を分けて 2 回実施し、2 回目は方式の順序を入れ替える (計 40 語) | 相殺される。作業量が倍 |
| 最低限 | 手作業 10 語 → AnkiFlow 10 語 を 1 回のみ | **相殺されない。AnkiFlow に有利に働く** |

「最低限」を選ぶ場合、その偏りが AnkiFlow 側に有利であることを報告書の制約の章に必ず記す。

### 4.5 計測の境界

曖昧さを残さないため、計測の開始と終了を定義する。

| 事項 | 定義 |
| --- | --- |
| 開始 | 対象の語を決めた**後**、最初の操作 (辞書を開く、入力欄に打ち込む等) を始めた瞬間 |
| 終了 | Anki への登録が完了し、次の語に取りかかれる状態になった瞬間 |
| 除外 | 中断 (電話、離席、無関係な作業)。ストップウォッチを止める |
| 除外 | 語を選ぶ時間。両方式に共通であり、差を生まない |
| 含める | 調べ物、やり直し、誤りの修正。これらは作業の一部である |
| 含める | AnkiFlow 側の AI 生成の待ち時間。利用者が待つ時間は所要時間である |

最後の項目は AnkiFlow に不利に働くが、利用者から見れば待ち時間も所要時間である。除外しない。

### 4.6 記録項目

**1 語ごとに**記録する。合計だけでは分布が分からない。

| 列 | 内容 |
| --- | --- |
| 通番 | 1〜20 |
| 語 | 対象の語 |
| 方式 | 手作業 / AnkiFlow |
| 語群 | A / B |
| 所要時間 | 秒 |
| 完成条件 | 達成 / 未達 (未達の場合は欠けた項目) |
| 備考 | 詰まった点、想定外の事象 |

記録用の表は報告書 (AF-EVL-002) 第 4 章に用意する。

### 4.7 集計

| # | 算出するもの |
| --- | --- |
| 1 | 方式ごとの中央値、平均、最小、最大 |
| 2 | 差 (手作業 − AnkiFlow) および短縮率 |
| 3 | 20 語すべての個票 |

**中央値を主たる代表値とする。** N が小さいため、1 件の外れ値が平均を大きく動かすためである。平均も併記する。

統計的検定は行わない。N=10 ずつでは検出力が乏しく、有意性を論じても意味を持たない。第 6 章に明記する。

### 4.8 実施条件

| 事項 | 取り決め |
| --- | --- |
| 実施環境 | 同一の PC、同一のブラウザ、同一のネットワーク |
| Anki | 起動済みの状態から始める。起動時間は含めない |
| 体調・時間帯 | 極端に疲労した状態では実施しない。実施日時を記録する |
| 中断 | 20 語を通しで行うことを原則とする。分割した場合は記録する |

## 5. M-02 から M-05 の測定

### 5.1 M-02 — 1 語あたりのカード種類数

AnkiFlow で 1 語を登録した際に生成される Anki ノート数を数える。手作業では、同じ枚数を作るのに要する追加時間が M-01 に含まれている。

| 方式 | 測定方法 |
| --- | --- |
| AnkiFlow | 実験で選択したカードタイプの数 |
| 手作業 | 同上 (等価性の定義により同数を作る) |

本指標は「1 回の入力で複数方向のカードを得る」という設計意図が働いているかの確認であり、比較指標ではない。

### 5.2 M-03 — 対応コンテンツタイプ数

計数のみ。2026-08-01 時点で組み込み 3 種 (語学・IT 用語・一般知識) に加え、利用者が任意に追加できる。語学は英語・中国語・日本語に対応する。

### 5.3 M-04 — カード 1 枚あたりの外部 API 費用

| # | 手順 |
| --- | --- |
| 1 | 実験の開始前に Anthropic Console で当月の使用量を記録する |
| 2 | 実験を実施する |
| 3 | 実験の終了後に再度記録する |
| 4 | 差分を AnkiFlow で作成した枚数で割る |

Firestore、Google Cloud TTS、Unsplash はいずれも無料枠の範囲内で運用する前提であり、費用は発生しない。前提の詳細は非機能要件書 (AF-NFR-001) 第 5 章に定める。実際に無料枠を超えていないかを、測定時にあわせて確認する。

### 5.4 M-05 — 通知経由の復習回数

`review_events` コレクションのうち、LINE 経由の評価による記録を数える。測定期間を定めて集計する。

## 6. 制約と限界

**本章は必読である。** 本測定の結果をどこまで信じてよいかを定める。

### 6.1 設計上の限界

| # | 限界 | 影響 |
| --- | --- | --- |
| 1 | **N が小さい。** 各方式 10 語 | 統計的な一般化はできない。傾向を示すにとどまる |
| 2 | **被験者が 1 名。** 開発者本人のみ | 他者にとって同じ効果があるかは不明 |
| 3 | **対照群がない。** 被験者内比較である | 個人差の影響を分離できない |
| 4 | **測定者と開発者が同一である** | 期待バイアスを排除できない。無意識に手作業側を丁寧に行う、あるいは急ぐ余地がある |
| 5 | **習熟度が方式間で異なる。** AnkiFlow を日常的に使っている | AnkiFlow 側に有利に働く |
| 6 | **単一セッションである** | 疲労、集中力、体調の影響を平均化できない |
| 7 | **品質の等価性は主観による判断である** | 第 4.2 節の条件を満たしても、内容の質が同等とは限らない |

限界 4 と 5 は本質的であり、設計で解消できない。開示することでのみ扱える。

### 6.2 主張してよいこと・してはならないこと

| 主張 | 可否 |
| --- | --- |
| 「この条件下で、私が測った限り、作成時間は N 秒から M 秒になった」 | ✅ 可 |
| 「開発者本人にとって作業負担は軽くなった」 | ✅ 可 |
| 「一般に作成時間が X% 短縮される」 | ❌ 不可。N=1 である |
| 「他の利用者も同じ効果を得られる」 | ❌ 不可。検証していない |
| 「統計的に有意である」 | ❌ 不可。検定を行わない |
| 「学習効果が向上した」 | ❌ 不可。第 6.3 節を参照 |

### 6.3 学習効果を測定しない理由

学習効果 (語彙が定着したか) を測るには、事前・事後のテスト、十分な期間、対照群、そして交絡要因の統制が要る。本測定はそのいずれも備えていない。

仮に「AnkiFlow 導入後に定着率が上がった」という数値が得られたとしても、次のいずれとも区別できない。

| 交絡要因 |
| --- |
| 学習を続けたことによる習熟 |
| 学習時間そのものの増減 |
| 扱う語彙の難易度の変化 |
| Anki 側の設定変更 |
| 生活環境や動機の変化 |

したがって学習効果は**仮説として提示するにとどめ、測定値をもって主張しない**。

### 6.4 学習効果に関する仮説と代替指標

主張はしないが、設計の意図として次の仮説を置く。

> 作成の負担が下がる → 作成を継続できる → 触れる語彙数が増える → 定着の機会が増える

この仮説を**傍証する**参考値として、次を報告書に添えてよい。ただしいずれも因果を示さない。

| 代替指標 | 得られるもの | 交絡 |
| --- | --- | --- |
| 月ごとの作成枚数の推移 | 継続できているか | 学習意欲の変動と区別できない |
| 連続作成日数 | 習慣化の度合い | 同上 |
| Anki の保持率 | 定着の状況 | 語彙の難易度、Anki の設定に依存する |

報告書ではこれらを「参考」の節に置き、結論の根拠として用いない。

## 8. 判定基準

**実施前に定める。** 結果を見てから基準を決めない。

| 指標 | 目標 | 根拠 |
| --- | --- | --- |
| M-01 | 作成時間の中央値が手作業の**半分以下** | カード作成の手間の解消が本システムの存在理由である。半分に届かなければ、導入と設定の手間に見合わない |
| M-02 | 1 語から 2 種類以上のカードを生成できる | 1 種類なら手作業と変わらない |
| M-03 | 3 種類以上のコンテンツタイプに対応する | 語学・IT・一般知識の 3 領域を想定した設計である |
| M-04 | 1 枚あたりの費用が実用に耐える水準である | 具体的な閾値は測定後に判断する。事前に額を定める根拠がない |
| M-05 | 通知経由の復習が実際に発生している | 0 回であれば機能が使われていない |

M-04 のみ数値目標を置かない。根拠のない閾値を先に置くことは、本書第 2.2 節の方針に反するためである。

目標に届かなかった場合も、その事実をそのまま報告書に記す。届かなかった指標を削除してはならない。
