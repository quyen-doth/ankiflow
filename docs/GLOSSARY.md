## 1. 本書の位置づけ

本書は、AnkiFlow の文書および実装で用いる用語を定義する。文書を読んでいて意味の取れない語に出会った場合、まず本書を参照する。

用語の表記は、実装上の識別子をそのまま用いる場合と、日本語に訳して用いる場合がある。本書では両者を併記する。文書中で英語の識別子を用いる場合は、原則としてコード書式 (`code`) を用いる。

画面名および UI のラベルは英語で実装されている。日本語の文中では英語のまま `「」` で囲み、説明を日本語で記す。

## 2. 業務に関する用語

| 用語 | 読み・別称 | 定義 |
| --- | --- | --- |
| エントリ | Entry、`entries` | 利用者が登録した語彙または知識の 1 件。AnkiFlow における最小の管理単位である。1 件のエントリから複数枚の Anki カードが生成される |
| カード | Card | Anki における出題の 1 単位。表面と裏面を持つ |
| ノート | Note | Anki における 1 件のデータ。1 件のノートから複数枚のカードが生成される。AnkiFlow は 1 エントリにつき、選択したカードタイプの数だけノートを作成する |
| デッキ | Deck、`decks` | Anki におけるカードの集まり。学習の単位となる |
| カードタイプ | Card Type、`card_types` | 出題の方向を定義する設定。「単語から意味」「音声から単語」など。1 件のエントリに対して複数を選択できる |
| コンテンツタイプ | Content Type、`content_types` | 扱う知識の種類を定義する設定。入力フォームの構成、AI の生成内容、および読み込むデータを決定する |
| カテゴリ | Category、`categories` | エントリの分類。利用者が自由に定義する |
| トピック | Topic、`topics` | IT 用語における主題の分類 |
| 学習言語 | Study Language | 学習の対象となる言語。入力する語がどの言語であるかを指す |
| 出力言語 | Output Language | AI が意味や説明を生成する際の言語。学習言語とは独立して設定する |
| 一括作成 | Batch | 複数の語をまとめて入力し、一度に生成する操作 |
| 遅延同期 | — | Anki が起動していない状態で内容を保存し、後からまとめて登録する運用 |
| 受動的復習 | — | 利用者が能動的に学習しない時間帯に、通知によって内容に触れる復習の形態 |

## 3. 技術に関する用語

| 用語 | 定義 |
| --- | --- |
| Anki | 間隔反復による学習を行うオープンソースのソフトウェア。AnkiFlow は出題と復習を Anki に委ねる |
| AnkiConnect | Anki Desktop に追加するアドオン。`localhost:8765` で HTTP の窓口を提供する。AnkiFlow は利用者のブラウザからこれを直接呼び出す |
| AnkiWeb | Anki の公式同期サービス。端末間の同期に用いる。AnkiFlow は関与しない |
| SRS | Spaced Repetition System。間隔反復による出題の仕組み。AnkiFlow は自前で実装せず、Anki に委ねる |
| FSRS | Free Spaced Repetition Scheduler。間隔反復のアルゴリズムの 1 つ。AnkiFlow は通知の対象を選ぶ際に用いる |
| Firestore | Google のドキュメント指向データベース。本システムのデータ保管先である |
| Admin SDK | サーバー側で用いる Firebase の SDK。Security Rules をすべてバイパスする |
| Client SDK | ブラウザ側で用いる Firebase の SDK。Security Rules の適用を受ける |
| Security Rules | Firestore のアクセス制御規則。クライアントからのアクセスにおける唯一の拠り所である |
| カスタムクレーム | Firebase の ID トークンに埋め込む任意の属性。管理者判定に用いる。付与後は再ログインを要する |
| セッションクッキー | httpOnly の `__session`。認証状態の保持に用いる。ブラウザの JavaScript から読み取れない |
| ミドルウェア | `middleware.ts`。クッキーの存在のみを確認する第 1 層。署名は検証しない |
| Server Component | Next.js において、サーバー側でのみ実行される React コンポーネント。本システムの既定である |
| Client Component | `'use client'` を宣言した React コンポーネント。ブラウザ側で実行される |
| CORS | Cross-Origin Resource Sharing。異なる出自への通信に対するブラウザの制限。AnkiConnect の利用には設定が必要である |
| ローカルネットワークアクセス制限 | 公開されたページから `localhost` への通信を遮断するブラウザ側の仕組み。アプリケーションでは回避できない |
| tool 呼び出し | AI に対して、自由な文章ではなく定義済みの構造で応答させる仕組み。生成結果の構造を保証するために用いる |
| AI 出力プロファイル | `ai_output_profiles`。AI が生成する項目とその指示をコンテンツタイプごとに定義する設定 |
| フィールドソース | Card Field Source。カードの表裏に配置する内容の種類。エントリのどの項目をどう描画するかを定める |

## 4. データに関する用語

| 用語 | 定義 |
| --- | --- |
| `user_id` | データの所有者を示す Firebase Auth の UID。利用者ごとのすべてのコレクションが保持する |
| `__defaults__` | 新規利用者へ複製されるテンプレートを示す特別な `user_id`。実在する UID ではない |
| `form_type` | 描画するフォーム、実行する AI の設定、および読み込むデータを決定するルーティング項目。誤った値は静かに誤動作を引き起こす |
| `code` | コンテンツタイプのルーティングキー。ドキュメント ID ではなくこの値でルーティングする。作成後は変更できない |
| `status` | エントリの状態。`draft` (作成中)、`reviewed` (確認済み、未登録)、`synced` (Anki へ登録済み) の 3 値を取る |
| スナップショット | グローバルの設定を利用者のワークスペースへ複製したもの。複製後は元の変更に追随しない |
| ワークスペース | 1 人の利用者が所有するデータの範囲。利用者間で完全に分離される |
| 派生フィールド | 問い合わせを成立させるために元の項目から算出して保持する項目。元の項目との整合を保つ必要があるため、変更はサーバー経由に限る |

## 5. 開発・運用に関する用語

| 用語 | 定義 |
| --- | --- |
| 検証仕様 | `verify/` に置く独自形式の試験。コンポーネントを描画し、その結果を DOM の表面から観察する |
| dry-run | 実際の変更を行わず、対象と差分のみを表示する実行方式。移行スクリプトの既定である |
| Release PR | `develop` から `main` へ差分を反映する自動生成 Pull Request。版を繰り上げる場合は `release: vX.Y.Z`、繰り上げない場合は同期 PR になる |
| 同期 PR | 文書・テスト・CI 設定のみの差分を、版・タグ・GitHub Release を変更せず `develop` から `main` へ反映する Release PR。タイトルは `release: developをmainへ同期` |
| Conventional Commits | コミットメッセージの規約。本プロジェクトでは種別を英語、要約を日本語で記す |
| 機能フラグ | `settings/global` が保持する、費用の発生する機能の有効・無効の設定。管理者が全体に適用する |

## 7. 用語の使い分け

同義に見えて区別を要する語を示す。文書を書く際はこの区別に従うこと。

| 区別 | 内容 |
| --- | --- |
| エントリとカード | エントリは AnkiFlow 側の管理単位、カードは Anki 側の出題単位である。1 件のエントリから複数枚のカードが生じる |
| カードとノート | ノートはデータ、カードは出題である。AnkiFlow が作成するのはノートであり、カードは Anki が生成する |
| コンテンツタイプとカードタイプ | コンテンツタイプは「何を扱うか」、カードタイプは「どう出題するか」である |
| 学習言語と出力言語 | 学習言語は学ぶ対象、出力言語は説明を記す言語である。両者は独立して設定する |
| `content_types` と `user_content_types` | 前者は管理者が編集するグローバルの複製元、後者は実行時に参照する利用者ごとの複製である |
| 管理者と利用者 | 管理者はアプリケーションの所有者であり、費用を負担する。利用者は招待を受けた学習者である |
| 一括作成と一括取り込み | 前者は画面上で複数語を入力する方式であり、実装済みである。後者はファイルからの取り込みを指し、未実装である |
